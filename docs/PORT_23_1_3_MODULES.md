# Порт 23.1.3 — модули оружия

## Задача

Все модули оружия должны добавляться игроку и быть максимального уровня — **X (10)**.
Версия и ветка: `23.1.3`, ABI `arm64-v8a`.

## Текущий статус

| Требование | Состояние |
|---|---|
| Уровень модулей = X | ✅ подтверждено на устройстве |
| Хуки не падают и не отключаются | ✅ подтверждено (`install incomplete` больше не появляется) |
| Каталог 42 модуля + 42 набора читается в рантайме | ✅ проверяется на старте (`catalogue verified`) |
| Каталог попадает в инвентарь игрока | 🟡 ревизия 4, ждёт проверки на устройстве |

## История ревизий

### Ревизия 1 — хук не встал

При правке файла два символа в имени геттера уровня были заменены на `十` (U+5341):
`丐` (U+4E10) и `丒` (U+4E12). Такого символа в метаданных 23.1.3 нет ни одного раза,
обязательный хук не разрешился, и fail-closed обёртка выключила всю фичу:

```
hook: REQUIRED method not found: 丐三七世丝丗与丛上.七且十东十丆丑丈万/0
23.1.3-modules: install incomplete, module disabled
```

Лечение: точные байты UTF-8 всех обфусцированных имён закреплены `static_assert`,
плюс отдельная проверка, что байтовой последовательности U+5341 нет ни в одном имени.
Теперь порча имени ломает сборку, а не устройство.

### Ревизия 2 — запись в поля, которые никто не читает

Каталог записывался в `ModulesController +0x40 / +0x48` и сбрасывал их. Эти поля
хранят модели хранилища предметов, а не инвентарь, поэтому на экране не изменилось
ничего.

### Ревизия 3 — мерж сработал, но не туда

Каталог вливался в `丟丅丁不丄丟不丑丁.七丌丑世丂丟丞丞丟()` (`0x028DB524`, 34 call site).
Мерж действительно выполнялся, но этот метод возвращает **модули, установленные в
конкретный предмет**: он единственный во всём образе вызывает
`专丂丄丈一丂世丑丏.丆丌丌丆且丙七丌丞(int)` (`0x0171F9D8`) — профильные записи по id предмета.

Последствия на устройстве ровно такие, как предсказывает архитектура:

* броня «носила» все 42 модуля — панель `Module Effects` переполнилась и наложила
  эффекты друг на друга (`Kinetic Damage 30%` десятками, `Turbo Charger` поверх текста);
* все модули в сетке погасли с оверлеем `Same mod type already in use`, потому что
  для любого модуля предмет уже «имел» его тип;
* количество модулей в «Арсенал → Модули» не изменилось, так как инвентарь читается
  из другого списка.

### Ревизия 4 — грант на стороне инвентаря

Каталог добавляется в два списка, которые реально перечисляют читатели хранилища:

```
ModulesController.丅与世丕业丘不丂丈  (+0x30, List<module>)
ModulesController.下丘丌一丞丛丂三丗  (+0x38, List<moduleSet>)
```

Особенность: геттеры этих полей (`0x0281473C` / `0x02814784`) имеют **0 call site** —
компилятор заинлайнил все чтения. Хукать их бессмысленно, поэтому грант сделан на
уровне полей:

1. `ModulesController.OnInstanceCreated` — захват экземпляра синглтона, грант после
   оригинала (синглтон как раз строит там свои списки);
2. перед `ModuleStorageView.上专丅丑丘丟丙东与`, `ModuleArmoryInfoScreen.上专丅丑丘丟丙东与` и
   `ModuleInsertPanel.上丘与丛丝业丆万丁` — сетка строится уже из расширенного списка, и
   если игра пересобрала список, он тут же восстанавливается;
3. пульс из главного меню каждые 30 кадров.

Сам объект списка никогда не подменяется — только дополняется через `List<T>.Add`
после проверки `Contains`. Подмена ссылки оставила бы все заинлайненные читатели с
старым экземпляром.

Модели предметов (`丟丅丁不丄丟不丑丁`) больше не трогаются вообще, поэтому эффект «вся
броня в модулях» уходит.

## Проверки перед пушем

1. Компиляция изолированной TU с заглушками:
   `g++ -std=c++17 -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Werror -fsyntax-only`
2. Сверка каждого обфусцированного имени с `dump2313.cs`, включая точные строки
   объявлений полей `+0x30` и `+0x38`.
3. Негативный тест: подмена одного символа имени поля на `十` должна валить сборку
   на `static_assert` (проверено — 2 срабатывания).

## Что смотреть в логе

```
adb logcat -c
adb logcat -s OPG3D | grep 23.1.3-modules
```

Ожидаемые строки:

```
23.1.3-modules: modules controller captured
23.1.3-modules: inventory routes installed 4/4
23.1.3-modules: catalogue verified (42 modules, 42 sets)
23.1.3-modules: inventory grant (controller ready): modules 4 +38 -> 42, sets 3 +39 -> 42
23.1.3-modules: module inventory complete (42/42 modules, 42/42 sets)
23.1.3-modules: displayed module level -> 10 (call 1)
23.1.3-modules: armed: level X guaranteed, catalogue granted into the ModulesController inventory lists
```

Если грант не проходит, строка сама называет причину:
`controller instance not seen yet`, `inventory field missing`, `inventory list is null`,
`catalogue getter returned null`, `inventory list api incomplete`, `catalogue is empty`.

Важно: лог надо снимать **после** захода в «Арсенал → Модули», а не во время
загрузки — предыдущие два дампа обрывались на `AppsMenu`, до главного меню, поэтому
рантайм-строк в них не было.
